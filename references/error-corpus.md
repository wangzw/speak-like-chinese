# 中文写作规范与错误样例库

> 用途：按章节查某类问题的病象、形式与例句；日常写作前的速查用上一级目录的 checklist.md。
> 数据来源：本机 Claude Code 全部会话历史，审查时点 2026-10-25 12:00。
> 覆盖 4,958 个转录文件、72,561 个中文文本块、约 288 万汉字，日期范围 2026-10-08 至 2026-10-25。
> 方法：先按分块双视角审读（语法、词法各一名），再由独立审校者逐条复核，最后逐字回查原文。共报出 17,347 条疑似问题，复核保留 7,305 条，其中 7,051 条的摘录在原转录中逐字命中（96.5%），去重后 7,047 条进入统计。

## 一、怎么用这份库

1. 日常写作不读这份库：短回复按 speak-like-chinese 的 core.md 常驻规则，长篇中文先看上一级目录的 checklist.md。它的落笔前自查、标点速查、高频硬译和“不算错误”几部分由本库压缩而来，另加比喻直译、自造术语和 AI 腔。使用中新发现的模式按日期追加在第十节。
2. 要弄清某类问题长什么样、怎么改，按标题打开第五节里对应的一节，不要整本读。
3. 第六节是完整的高频误用词表，第八节列出**不算错误**的说法。落笔前自查见 checklist.md 第一章，标点速查见 checklist.md 2.1。
4. 引号体例：本机一律用“”（内层‘’），不用直角引号 `「」`、`『』`。第五节的“原文”行和附录一的否决理由保留当时的写法作为证据，其余文字已统一。

## 四、十个典型错例

这十句是语料里最能说明病因的病句，各取一例；数量最多的标点问题见 checklist.md 2.1。

**1. 英文名词被音译成人名。** 原文“我查看会话哈里斯剩余的脚本键与已有密码注册用例”把 harness 音译成“哈里斯”，读者会以为在说某个人。这个词保留英文并加代码标记，写成 `harness`。

**2. 只取英文的词形，不取汉语的义项。** 原文“加＝改 `pkg/http` 接口面 + 金榜 + 立 ADR”用“金榜”指 golden 基准清单。金榜在汉语里是科举榜文，与 golden 无关。应写 `golden` 基准清单。

**3. 中文里用英文直引号。** 原文 `所以审查者说的"已补的一半有效、另一半没有用例"属实。` 中文句子里的引号要用“”。这是全库数量最多的单项问题，脚本扫出 7,796 处。应写“所以审查者说的‘已补的一半有效，另一半没有用例’属实。”

**4. 同一个硬译反复出现。** 原文“没有 git 操作，主检出没有动。”把 main checkout 译成“主检出”，语料里出现 731 次。“检出”是动作，不能当处所。应写“没有 git 操作，主工作树没有动。”

**5. 一字之差，指称就错了。** 原文 `未找到 → ErrNotFound（未读/他人/他租户三合一）`，“未读”应为“未知 id”。未读消息是查得到的，写成未读，三种归并情形就少了一种。

**6. 别字与漏字。** 原文“**权摘**：代价是……”，应为“权衡”；原文“看看现状与 emotion 媒查询文本”漏了“体”，应为“媒体查询”。前一处既不同音也不形近，后一处是漏字，都是生成时的差错，读者要停下来猜。

**7. 定语位置错了，主语就变了。** 原文“工作树是干净的相关部分”读起来像在说“工作树是一种部分”，原意是“工作树的相关部分是干净的”。

**8. 缺中心语，又把两句话说成一句。** 原文“它是一个纯读（无副作用、无请求体、响应可缓存语义上是查询）”，“一个纯读”没有中心语；括号里“响应可缓存”和“语义上是查询”挤在一起。应写“它是纯读操作（无副作用、无请求体，语义上是可缓存的查询）”。

**9. 把字句用错了动词。** 原文“但把 demo 自带一个真实 seed 会与……有张力”，“自带”不是处置动词，不能用“把”。应写“但让 demo 自带一个真实的 seed，会与……相冲突”。

**10. 动宾关系颠倒。** 原文“依赖注入风格总结（照抄这个新模块时必须保持）”把要照抄的对象说成了新模块，实际是照抄 `pkg/foo` 的写法。应写“新模块照抄这套写法时必须保持”。

## 五、错误样例库（按类别）

每条模式按“病象 → 形式 → 实例 → 自查”四段写。实例的原文逐字摘自会话历史，改写只动出问题的部分。
标“✅ 双视角通过”的条目已经两名独立审校者交叉核实：一人判断问题是否成立，一人判断改写是否自然准确。标“存疑”的条目未经双视角核实，保留供参考。

### 5.1 标点与体例

#### 5.1.1 标点误用（中英文标点混用）（语料 1928 条）

**中文句内半角分号**　存疑（未双视角核实）

- 病象：中文并列分句之间用全角分号“；”。写成半角 `;` 是英文习惯，排出来只有半个字位，分句的界限因此变弱。
- 形式：`分句 A; 分句 B`；高频形态：`……;而……`、`……;故……`
- 实例：
  - 原文：构建产物 `dist/foo.js:117` 与源码一致;ADR 未对重复 id 另作裁定,
  - 改写：构建产物 `dist/foo.js:117` 与源码一致；ADR 未对重复 id 另作裁定，
  - 原文：全树 ADR 里只有这一处链到 `design/`。标准规定 ADR 不回链设计;提交 abc1234 刚清过同类。
  - 改写：全树 ADR 里只有这一处链到 `design/`。标准规定 ADR 不回链设计；提交 abc1234 刚清过同类。
- 自查：两个分句之间是半角 `;` 吗？改成全角分号“；”。

**英文直引号包中文**　✅ 双视角通过

- 病象：中文正文的引述、强调要用成对的全角弯引号“”（内层用‘’），直接敲 ASCII 直引号 `"` 字距窄、不成弯，夹在汉字里像代码，还会和全篇引号体例打架。
- 形式：`中文 + "X" + 中文`；高频出现在“说”“称”“写”“标”“所谓”“那句”“这条”“确认”“写明”之后；英文短语也用全角引号，标识符改用反引号；引号两侧不留空格。
- 实例：
  - 原文：所以审查者说的"已补的一半有效、另一半没有用例"属实。
  - 改写：所以审查者说的“已补的一半有效，另一半没有用例”属实。
  - 原文：原文"空体请求映射成 400"没有 gin 实测依据，已删去。
  - 改写：原文“空体请求映射成 400”没有 gin 实测依据，已删去。
  - 原文：确认有无"同一词串只能一义"的条款。
  - 改写：确认有无“同一词串只能一义”的条款。
- 自查：句子里出现 ASCII 的 `"` 了吗？统一换成“”；引号两侧不要留空格。

**中文句内半角逗号**　✅ 双视角通过

- 病象：中文分句之间的停顿用全角逗号“，”，半角逗号 `,` 只有半个字位，夹在汉字或代码标识之间会让句子像英文从句，读起来断裂。
- 形式：汉字或代码标识 + `,` + 汉字；高频位置：分句之间（`,并`、`,而`、`,故`、`,而非`）、插入语前后，以及逗号后多带一个空格的 `, `。并列词语之间的半角逗号改顿号。
- 实例：
  - 原文：我微调一下设计文档的标点,并跑一次针对新用例的详细测试确认覆盖。
  - 改写：我微调一下设计文档的标点，并跑一次针对新用例的详细测试确认覆盖。
  - 原文：我没有改动 W 下任何文件,实验都在 `/tmp/review-consistency/`。
  - 改写：我没有改动 W 下任何文件，实验都在 `/tmp/review-consistency/`。
  - 原文：我重新核对 design-foo.md 的当前状态,避免与并行编辑冲突。
  - 改写：我重新核对 design-foo.md 的当前状态，避免与并行编辑冲突。
  - 原文：复数形式是 **(数量, 语言)** 的函数。
  - 改写：复数形式是 **（数量、语言）** 的函数。
- 自查：除去代码内部，汉字或代码标识后面是半角逗号吗？分句之间改成全角逗号“，”，并列词语之间改成顿号“、”。

**中文句内半角冒号**　✅ 双视角通过

- 病象：中文的提示、列举和解释前用全角冒号“：”，半角冒号 `:` 紧跟汉字时字距不足，还容易被误认成代码里的键值分隔符。
- 形式：汉字 + `:` + 说明或列表；高频触发：`汇总:`、`结论:`、`关键事实:`、`自检:`、`规则:`、`写明:`、`位置:`、`确认方式:`，以及冒号后多打一个空格的 `: `。
- 实例：
  - 原文：核对完成。汇总:
  - 改写：核对完成。汇总：
  - 原文：受守卫词表规则:provider 令牌未知时应渲染通用「其它」标签,而非原样名字
  - 改写：受守卫词表规则：provider 令牌未知时应渲染通用“其他”标签，而非原样名字
  - 原文：L171 正文判定主体: `调用方的账户`
  - 改写：L171 正文判定主体：`调用方的账户`
- 自查：中文提示语后面是半角冒号 `:` 吗？换成全角冒号“：”，别让它看起来像代码键值分隔符。

**中文括号用半角**　✅ 双视角通过

- 病象：中文行文里的夹注、补充说明和编号要用全角圆括号（），半角 `()` 夹在汉字中间既挤又像代码，同一句里还常与全角括号前后不一。
- 形式：汉字 + `(说明)` + 汉字；高频形态：`X(含 …)`、`(方法, 路径)`→`（方法、路径）`、`会话(67890)`、`文件(N)`、代码锚点后的说明，以及同一句前半用（）后半用 `()` 的混搭。
- 实例：
  - 原文：**15. 对已列清单的计数(措辞边缘)。**
  - 改写：**15. 对已列清单的计数（措辞边缘）。**
  - 原文：`deps_test.go`(http 与 observability)的预算与设计文字一致。
  - 改写：`deps_test.go`（http 与 observability）的预算与设计文字一致。
  - 原文：gopls 12345（cwd=wt-a）的父进程正是 wt-b 会话(67890)
  - 改写：gopls 12345（cwd=wt-a）的父进程正是 wt-b 会话（67890）
- 自查：汉字中间夹着半角 `()` 吗？换成全角（），再回头看同一句另一个括号是不是全角。

**直角引号与引号混用**　✅ 双视角通过

- 病象：同一篇文字里引号体例必须统一，不能把直角引号 `「」` 和弯引号“”轮换使用，否则读者会误以为不同引号代表不同层级或来源。本机的体例是“”（内层‘’）；直角引号 `「」` `『』` 是港台和竖排习惯，不用，旧文里遇到也改成“”。
- 形式：用 `「」` `『』`，或同一段里 `「」` 与“”并存；ASCII 直引号见本节“英文直引号包中文”。一律改为“X”。
- 实例：
  - 原文：一个功能目录内含"接口根包（不登记）+ 多个登记模块"，用一篇扁平文档承载，含「登记单元与名字」表
  - 改写：一个功能目录内含“接口根包（不登记）+ 多个登记模块”，用一篇扁平文档承载，含“登记单元与名字”表
  - 原文：且"非职责"要明写「由谁承担」
  - 改写：且“非职责”要明写“由谁承担”
- 自查：这一句用的是“”（内层‘’）吗？还有没有 `「」` `『』`？

**破折号、省略号写短**　✅ 双视角通过

- 病象：作破折号时必须写成 `——`（占两个字位），两侧不留空格；只写单个 `—` 是把连接号误当破折号。数字、地名、时间区间里的单个 `—` 是连接号（一字线），如 `北京—上海`、`2020—2021 年`，属正确用法，不在本条范围内。省略号须写六个点 `……`，单个 `…` 或三点 `...` 都不合中文体例。代码或原文引用里的截断符号不按本条判错。本机自己的正文不用破折号，见 10.6；本条只管破折号和省略号写得对不对。
- 形式：作破折号用的 `A — B`、`A—B` 改为 `A——B`，两侧不留空格；`…`、`...` 改为 `……`。标题、副标题、解释性插入、引文截断和列举未尽同样处理，常与引号问题同时出现。
- 实例：
  - 原文：而 `to` 也随参数表进 `Resolve` — 这条连带判据要写进文档。
  - 改写：而 `to` 也随参数表进 `Resolve`——这条连带判据要写进文档。
  - 原文：**缺陷一 — 任何真实目录都装不进来（确定性）**
  - 改写：**缺陷一——任何真实目录都装不进来（确定性）**
  - 原文：（`:263`、`:489`、`:1097`、`:1206`、`:1319`…）
  - 改写：（`:263`、`:489`、`:1097`、`:1206`、`:1319`……）
- 自查：破折号是不是两个字宽，两边有没有空格？省略号是不是六个点？遇到单个 `—`，先看它是不是连接号，是连接号就不改。

**ASCII 单引号**　✅ 双视角通过

- 病象：引语内部再引用时，中文的层级是外层“”、内层‘’；ASCII 单引号既不合中文宽度，也不承担这层引用功能。中文行文里独立引用词语应使用双引号“X”，只有在外层已经是双引号时才降为单引号‘X’；无论哪种情况都不应保留 ASCII 单引号。
- 形式：外层用 `"…"`、内层用 `'…'`；或中文行文里单独用 `'X'` 标示词语；常见于转述审查意见、引用旧结论时再套一层引语。
- 实例：
  - 原文：确认审查者说的"被引用的 ADR 已改成'参与的就是哪个'"是否属实。
  - 改写：确认审查者说的“被引用的 ADR 已改成‘参与的就是哪个’”是否属实。
  - 原文：计划里第 5 条写的是"现有 Stop/Close 已按'容忍 nil 或别的类型'写"。
  - 改写：计划里第 5 条写的是“现有 Stop/Close 已按‘容忍 nil 或别的类型’写”。
  - 原文：其中'不用 X 库'的结论已被 [ADR-1] 取代
  - 改写：其中“不用 X 库”的结论已被 [ADR-1] 取代
- 自查：引语里再套引语时，外层是“”、内层是‘’吗？没有外层引号时，单独引用的词语用“”，不用‘’。不要留下 ASCII 的 `'…'`。

**符号代替连词与数值范围**　存疑（未双视角核实）

#### 5.1.2 标点误用（其他）（语料 474 条）

**顿号连接分句**　✅ 双视角通过

- 病象：顿号只分隔并列的词语或短语。两个各自具备主语和谓语、能独立成句的分句之间不能用顿号，否则读者会把后一分句读成前一句的并列成分。共用同一主语或同一谓语的并列成分（如“她的工作是收信、发信”）仍用顿号；两个分句之间用逗号，若并列分句内部已含逗号，分句间改用分号。
- 形式：出现“A 是 X、B 是 Y”“A 已就位、B 无输出”这类两个完整主谓结构时，顿号一律改逗号；分句内部已有逗号时，分句之间改分号。高频触发：是、属、已、均、会、要、不能、了。
- 实例：
  - 原文：设计已落 main、并行会话按同一结果对齐
  - 改写：设计已合入 main，并行会话按同一结果对齐

  - 改写：SSO 表单的协议是自由文本，配置是裸 JSON。
  - 原文：目录仍是 JSON、语法是自家的，但等于自己维护一层语法与校验。
  - 改写：目录仍是 JSON，语法是自家的，但等于自己维护一层语法与校验。
- 自查：顿号两边是不是各有一个主语加谓语，都能独立成句？是就换逗号；分句内部已有逗号时，分句之间换分号。

**缺逗号致粘连**　✅ 双视角通过

- 病象：该停顿的地方没停，相邻汉字会临时拼出别的词，或把后句并进前句，意思就走样了。
- 形式：“任务一并在”“点进去后端”“按 ADR 标准已发布”这类相邻字面能重组的接缝；句首介词短语之后、补充说明和插入语前后补逗号。

  - 改写：我已完成任务一，并在任务二上取得明确结论

  - 改写：该记录状态为“已被取代”，按 ADR 标准，已发布记录的决策不可改

**做字套长定语**　✅ 双视角通过

#### 5.2.5 繁简、异形词与地区词混用（语料 6 条）

  - 改写：`cursor`、`limit`，其他参数会返回 400

- 自查：写完把每个双字词默读一遍：这个词真的存在吗？

**同音笔误**　✅ 双视角通过

- 病象：键入了与目标词读音、字形或词义联想相近的另一个词，或漏写一个字；句子表面通顺，所指已经改变。包括同音近音、形近和常用词联想误替。双字词里只错一个字、结果不成词的，见上条“单字别字”。
- 形式：误写（本意）。同音近音替换：未读（未知）、公式（表单）、引擎（engineer）、正则化（正好）、出行（输出）、清新（全新）；漏字或形近：三合（三种情形）、架构好（架构上）。触发：句中冒出一个与上下文不搭的常用词时，放慢读一遍。
- 实例：
  - 原文：未找到 → `ErrNotFound`（未读/他人/他租户**三合一**）
  - 改写：未找到时返回 `ErrNotFound`（未知/他人/他租户**三合一**）
  - 原文：**推断**：把字段预览提前写进描述符，能让公式在起流程前渲染（保住今天的 UX）
  - 改写：**推断**：把字段预览提前写进描述符，能让表单在发起流程前渲染（保住今天的 UX）
  - 原文：三合同形与 Delete 幂等属错误语义，判据明确把错误语义列为本模块本职
  - 改写：三种情形返回同样的结果，Delete 也是幂等的，这两点都属错误语义，判据明确把错误语义列为本模块本职
- 自查：把这个词读出声，是不是另一个词？

**同音词形混用**　✅ 双视角通过

- 病象：两个读音相同或相近的词（含虚词）在汉语里都存在，但词性或语法功能不同，落笔时选错。典型：截至（介词，后接时间，如“截至目前”）/截止（不及物动词，表示到点停止，不能带时间宾语）；必需（动词/形容词，可作定语）/必须（副词，作状语）；指明（指出、说明）/指名（点名，多用于人）；补语标记“得”/定语标记“的”。
- 形式：高频对立：截至/截止（时间点前用截至）、必需/必须（定语用必需）、指明/指名、走岔/走叉、得/的（补语前用得）
- 实例：
  - 原文：门禁退出 1 并指名该文件与实际可用的标签（`integration, race`）。
  - 改写：门禁退出 1 并指出该文件与实际可用的标签（`integration, race`）。
- 自查：时间点前是“截至”，定语是“必需”，补语前是“得”。先想词性再落笔。

**多字漏字**　✅ 双视角通过

- 病象：多打一个字（衍字）或漏一个字（脱字），使词语不成词或句子读不通。整词被换成不相干的词属于错词、别字，不计入本条。
- 形式：误写（本字）：实测评（实测）、用例子（用例）、在场所（在场）、项目管管理（项目管理）、按时代码（按代码）、分支机（分支机制）。
- 实例：
  - 原文：切片 1 的实现状态行还没按时代码更新
  - 改写：切片 1 的实现状态行还没按代码更新
- 自查：句子读不通时，先数一数字数：是不是多打或漏打了字？

**同义成分叠用**：见 5.3.9“同义叠床架屋”。

**外文专名拼错**

- 病象：拉丁字母的专名、缩写拼错一个字母，读者会以为是另一样东西，例如 ADB 通常指安卓调试桥。
- 形式：缩写错一个字母（ADB、ADPR 应为 ADR）；厂商名错拼（Vanage 应为 Vonage）。
- 实例：
  - 原文：ADB 自己的「考虑过的选项」里就把「migrate 纳入全部模块」当作可自由权衡的备选项否决
  - 改写：ADR 自己的“考虑过的选项”里就把“migrate 纳入全部模块”当作可自由权衡的备选项否决
  - 原文：定位所有需要按裁定修改的点（哨兵、路由括号、计数、位置指代、ADPR 链接）
  - 改写：定位所有需要按裁定修改的点（哨兵、路由括号、计数、位置指代、ADR 链接）
  - 原文：**Vanage / Sinch / Infobip 的分水岭不是 API，而是目的地国家组合**
  - 改写：**Vonage / Sinch / Infobip 的分水岭不是 API，而是目的地国家组合**
- 自查：专名和缩写跟前文、跟官方写法对得上吗？

### 5.3 句法与搭配

#### 5.3.1 欧化句式/翻译腔（语料 462 条）

**英文实词、习语硬译与望文生义**　✅ 双视角通过

- 病象：把英文单词或习语按字面义或错误义项逐词换成中文，字面可读但所指概念与原文不符；判定标准是该中文词在上下文中是否真的指称原概念，而不是它是否曾被人这样译过。英文复合词和习语是整体词义，按词素逐个替换往往得不到汉语词。first-class 译“一等公民”是通行说法，不要矫枉过正。
- 形式：shape→形状、leg→腿/测试腿、in flight→在飞、load-bearing→载荷性/承重、live tree→活树、seam→接缝、main checkout→主检出、engineering mechanism→工程机械、design authority→设计权威、fixture→夹片、first-class→第一等、negative assertion→负数断言、presence→在场、forces→力量、lives in→住在、fail loudly→响亮失败、blessed→被祝福的、workable→可工作的、lowest common denominator→最低公共分母、theoretical floor→理论地板。
- 实例：
  - 原文：所以这处 `replace` 是载荷性的、不是随手加的。恢复它。
  - 改写：所以这处 `replace` 是必不可少的，不是随手加的。恢复它。
  - 原文：门禁在测试腿红了。看细节。
  - 改写：门禁在测试环节红了。看细节。
  - 原文：**等待重试**而不是直接失败（改工程机械，更可靠）
  - 改写：**等待重试**而不是直接失败（改的是工程机制，更可靠）
  - 原文：其 real-client 挡板对未脚本请求"响亮失败"
  - 改写：其 real-client 测试桩对未预置应答的请求会直接报错
- 自查：不看英文，中文读者能从这个词读出它在这里指的东西吗？读不出，或读成别的意思（腿、在飞、工程机械），就是硬译；再查中文里同一概念怎么说。
- 5.2.1 原“英文复合词与习语逐词直译”已并入本条。

**中英混杂：英文词充当谓语或宾语**：见 5.2.4“英文词作谓语”。

**英语句式与介词搭配直搬**　✅ 双视角通过

- 病象：照英语的固定句架、介词搭配、被动语态和否定结构造句，词都译了，语序和视角仍不是汉语；只针对整体句架生硬的情况，不包含“被定义为”这类已经归化的表达。照搬的结果常是成分残缺：长定语后面没有谓语，或者拿“无条件”这类状语直接当谓语。
- 形式：be defined as→“被 X 定义为”；fail with X→“以……错误失败”；fail on→“对……失败”；add X to Y→“补 X 到 Y”；release X to Y→“释放 X 给 Y”；have X on Y→“你有 X 在 Y”；on 401→“在 401 上”；be served→“被（重新）服务”；This is why→“这就是为什么”；exists as→“作为……存在于……”；zero→“登记零模块”；cannot…without→“无法……而不……”；长定语后缺谓语；状语直接作谓语（硬化头无条件）；“对 X 相关”→“与 X 相关”；条件状语后置；unique 译成“唯一”后直接接数量词。
- 实例：
  - 原文：日志提供者的 `Named` 返回 nil 时，启动以带模块名的错误失败，不再 panic。
  - 改写：日志提供者的 `Named` 返回 nil 时，启动会失败并报出带模块名的错误，不再 panic。
  - 原文：ui-a 的 `FooSection` 在 401 上**正确**地弹了升级窗
  - 改写：ui-a 的 `FooSection` 收到 401 时**正确**地弹出了升级窗
  - 原文：**核心包登记零模块**，每个后端在自己的 `init` 里登记。
  - 改写：**核心包不登记任何模块**，每个后端在自己的 `init` 里登记。
  - 原文：可使已删除租户被重新服务，或释放其别名给新租户
  - 改写：可使系统重新为已删除租户提供服务，或把其别名释放给新租户
  - 原文：内容端点两条硬化头**无条件**：`X-Content-Type-Options: nosniff`
  - 改写：内容端点无条件设置两条安全加固响应头：`X-Content-Type-Options: nosniff`
  - 原文：`Register` godoc 的三条 panic 情形，对 jobs 设计直接相关
  - 改写：`Register` godoc 的三条 panic 情形，与 jobs 的设计直接相关
- 自查：这个介词结构或句架，不看英文能直接读懂吗？“在……上”“以……失败”“对……失败”是不是 on、with 的对译？是就改成“收到……时”“遇到……时报错”。每个分句都找得到主语和谓语吗？找不到就补；语序不对就按中文重排。
- 5.2.1 原“英文句法照搬致成分残缺”已并入本条，其中被动式的一例归入 5.3.6“英文被动谓语直译”。

**英文介词短语直接作谓语**　✅ 双视角通过

- 病象：照搬英文里由介词短语充当的成分，把“按 X”“到 X”直接当谓语用，漏掉汉语必需的动词。来源多是英文的省略写法：connections per replica 写成“连接按副本”，pipe to `tail` 写成“管道到 `tail`”，connections scoped by X 写成“连接按 X 作用域”。压缩到主干后句子没有谓语，读者只能猜。
- 形式：“连接按副本”缺“划分”；“连接按 X 作用域”缺“限定”；“管道到 `tail`”缺“用管道接到”。
- 实例：
  - 原文：(1) 连接按副本；(2) 连接按 (tenant, recipient) **作用域**，匹配在缓冲之前
  - 改写：(1) 连接按副本划分；(2) 连接按 (tenant, recipient) **限定作用域**，匹配在缓冲之前
  - 原文：管道到 `tail` 会让退出码变成 `tail` 的——读日志文本才算数。
  - 改写：用管道接到 `tail` 后，退出码会变成 `tail` 的，要读日志文本才算数。
- 自查：句中的“按 X”“到 X”是不是 per、to、by 的对译？压缩到主干后还有谓语动词吗？没有就补上“划分”“限定”“接到”这类动词。

**动词名词化**　✅ 双视角通过

- 病象：本该用动词谓语的动作被写成“对……的××”“有××”“××的出现/采用/识别”等抽象名词结构，句子只剩名词，看不出谁做什么；仅指过度名词化，不含汉语中正常、简洁的“对……的处理”类表达。
- 形式：“完成/进行 + 对 X 的 V”“对 X 有识别”“X 的所有出现 / 全部出现”“X 的采用”“X 的提及”“X 的判定”“X 的存在性”“我的运行”。
- 实例：
  - 原文：接下来全树搜 `Supply` 的所有出现，核对签名与用法是否统一为新形态
  - 改写：接下来在全树搜索 `Supply` 出现的所有位置，核对签名与用法是否统一为新形态
  - 原文：规则对「接收者方法里直接调用该字段」的形态有识别。
  - 改写：规则能识别“接收者方法里直接调用该字段”这种形态。
  - 原文：我已完成对 module-a 区域的阅读、对 diff 的逐段核对
  - 改写：我已读完 module-a 区域，并逐段核对了 diff
- 自查：谓语是不是“是/有/完成/进行 + 抽象名词”？是就把它还原成动词再读。

**“的”字长定语套叠**　✅ 双视角通过

- 病象：把英语的后置定语从句、介词短语整体前置成“……的”，一句里连用三个及以上“的”，中心语被推到句尾，读者要回头重读才知道说的是什么；只指“的”字定语套叠，不含单纯的名词连写或形容词堆叠。
- 形式：“A 的 B 的 C 的 D”结构；定语里再套括注或并列短语；中心语常是“处置/判定/实现/签名”等抽象名词。
- 实例：
  - 原文：它正是设计文档反复说的"授权模块应持有、authn 不认识"的东西的样例实现。
  - 改写：它是一个样例实现，对应设计文档反复提到的那类东西：应由授权模块持有，authn 不认识。
- 自查：中心语前面有几个“的”？三个及以上就把长定语拆成两小句，或改写成谓语。

#### 5.3.2 搭配不当（语料 451 条）

**动宾搭配错位**　✅ 双视角通过

- 病象：动词与宾语在语义场上不兼容：字面可连读，但该动词的常规受事范畴不包含这个宾语，尤其是泛义动词硬接抽象名词或小句。判断标准是能否用“对这个对象做该动作”自然改写；能自然改写的不算错。
- 形式：写成“动词 + 抽象名词/小句”时，先问这个动词平时能带什么宾语。高频误配：收窄（严重度）、点名（小句）、加强（缺口）、省掉（风险）、推翻（担忧）、解决（根因）、搭建（依赖）、备份（校验和）、修（一致性）、核对（……一致）。
- 实例：
  - 原文：前端包对准入步进没有统一对话框，加强了宿主侧缺口
  - 改写：前端包对准入校验没有统一对话框，这进一步凸显了宿主侧的缺口
  - 原文：我删掉临时分支，正确重做了一遍，并逐笔核对每一笔的树与原提交完全一致。
  - 改写：我删掉临时分支，正确重做了一遍，并逐笔核对，确认每一笔的树都与原提交完全一致。
- 自查：这个动词平时带什么宾语？把它换成“对它做什么”念一遍，动作落得到这个对象上吗？

**主谓与判断句搭配错位**　✅ 双视角通过

- 病象：主语是事物或抽象名词时，谓语或表语却只适用于另一类主体（施事者、做法、位置等），句子因此不成立；判断句“A 是 B”中 A 与 B 必须属于同一语义范畴。
- 形式：主语是“缺口/状态/日志/摘要”等名词时，核对谓语是否真能用在它身上，如“缺口落地了”实指“补缺口的改动落地了”；写“A 是 B”前核对 A、B 是否同一范畴，触发：是……的做法、是……位置、扫描是……、条件很……、……说不通这种读法。
- 实例：
  - 原文：`code-foo` 的五处缺口也落地了，而且几处比审查员的原版更严
  - 改写：`code-foo` 针对五处缺口的测试也落地了，而且几处比审查员的原版更严
  - 原文：该判据对「单元 vs 集成」这一对被审性质不可区分。
  - 改写：该判据区分不了“单元 vs 集成”这一对被审性质。
  - 原文：把通行密钥用作**主登录方式**（不是第二因素）的站点，国际上已经是主流做法。
  - 改写：把通行密钥用作**主登录方式**（而不是第二因素），在国际上已经是主流做法。
  - 原文：扫描是 `./...`，所以新子包的包一定进 `scanned`
  - 改写：扫描范围是 `./...`，所以新子包一定会进入 `scanned`
- 自查：这个谓语能直接说这个主语吗？“A 是 B”里的 A 和 B 是同一类东西吗？

**不及物动词带宾语**　✅ 双视角通过

- 病象：不及物动词或状态词被当成及物动词直接带受事宾语，或硬接“为/入”等补语而缺少“到、于、在、给、使”等标记，多由英文动词逐词直译造成。注意“回到/回落到 + 处所或数值”本身合法，只有把字句或带受事宾语时才构成错误。
- 形式：“把……回到”→“把……回退到”；“回落 + 宾语”→“回退到”；“归因给”→“归因于”；“失效它”→“使它失效”；“不成立为”→“不能认定为”；“把……等完”→“等……跑完”；高频触发：失效、成立、回到、回落、归因、冻结。
- 实例：
  - 原文：把 `dispatch.go` 临时回到提交版后
  - 改写：把 `dispatch.go` 临时回退到提交版后
  - 原文：写入成功后失效它改变的每个屏上读（角色删除按租户失效账户绑定查询、标识删除失效账户列表
  - 改写：写入成功后，使它影响到的各个页面查询失效（删除角色时按租户使账户绑定查询失效；删除标识时使账户列表失效……）
  - 原文：它不成立为「外部施加的需求内容」，理由集中在三点
  - 改写：它不能认定为“外部施加的需求内容”，理由集中在三点
- 自查：这个动词能单独带宾语吗？不能就补“到/于/使”，或换成及物动词。

**生造压缩词**：见 5.2.2“生造缩略词（截字造词）”。

**量词与数量失配**　✅ 双视角通过

- 病象：量词按外形或习惯随手取，与名词语类不符（如“份 agent”“句行为”）；或数词后该有的量词、中心语在成句行文中被省略，导致数量关系失真。表格单元格和统计行可以省量词，句子和句中括号注不省，见 5.4.1“数字悬空”。
- 形式：写“一量+名”先确认量词与名词语类（人/agent 用“个”，行为/语义用“个/条”，文件、测试前补“个”）；省掉的中心语补回来；高频错配：份 agent、条 面、条 壳、一句行为、一处语义、两条资源。
- 实例：
  - 原文：那份 agent 担心的「次序细节丢失」因此无损，迁移时补一句即可。
  - 改写：那个 agent 担心的次序细节因此并未丢失，迁移时补一句即可。
  - 原文：设计文档已把「交付保证」写成设计结论，并在失败表里重现了这句行为。

#### 5.3.3 成分残缺或赘余（语料 782 条）

**谓语残缺**　✅ 双视角通过

- 病象：主语后面没有落到实处的谓语动词：名词、形容词、状态码或代码标识符被直接当成动作，状语铺完后句子也停在一半。

- 实例：

  - 改写：重复提交应返回同一结果，不能再扣一次款。
  - 说明：本例为自拟。
  - 原文：该裁定也没有 ADR 承载，需你定怎么落
  - 改写：该裁定也没有 ADR 记录，需要你决定怎么写进文档

**中心语残缺**　✅ 双视角通过

**及物动词缺宾语**　✅ 双视角通过

**句式杂糅**

- 病象：两个各自能独立成立的句式被强行揉进一句、共用一套成分，结果哪个句式都不完整；判断关键是句中有两套互相冲突的骨架，而不是句子长、能拆成两句。“是否……还是”这一种见 5.3.5“是否还是句式杂糅”。

#### 5.3.4 语序不当（语料 124 条）

**状语位置与层序错误**　✅ 双视角通过

- 病象：需要前置的状语（尤其是“向/对/给”引导的对象状语、“在……下”引导的条件状语、“经/按/从”引导的依据或方式状语）不能跑到动词或宾语之后；多层状语按时间、处所、条件、对象或方式的先后排列。注意：动词后直接带“在/到”构成动补（坐在椅子上、写在纸上、放在桌上、住在北京）是合法结构，不属于本条；本条针对的是本该作状语却后置的情况，以及状语层序颠倒。
- 形式：“V +（宾语）+ 在/于/从 + 处所”→“在/于 + 处所 + V”；“向 A + 在 B 下 + V”→“在 B 下 + 向 A + V”。高频触发词：在、于、从、向、按、已。
- 实例：
  - 原文：服务已重启在 8080。
  - 改写：服务已重启，监听 8080 端口。
  - 原文：数字按语言格式化经 `message.Printer`
  - 改写：数字由 `message.Printer` 按语言格式化
  - 原文：要求**向令牌端点与受保护路由在依赖故障下发请求，应答须是 503 且不含依赖种类
  - 改写：要求**在依赖故障下向令牌端点与受保护路由发请求**，应答须为 503，且不暴露依赖种类
- 自查：句中的“在/于/从/向 + 处所”是不是跑到了动词后？多层状语时，条件状语是不是排在对象状语后面？挪回原位再读一遍。

**定语语序错乱**　✅ 双视角通过

- 病象：定语应位于中心语之前并以“的”收口，多层定语按领属、数量、修饰排列；修饰方向不能颠倒（想说“交互依赖悬停”不能写成“悬停依赖的交互”），句末也不得留下无所依附的“的”。
- 形式：“中心语 + 可能……的，”→“可能……的 + 中心语”；“X 依赖的 Y”→“依赖 X 的 Y”；“端点各已登记路由”→“各端点已登记的路由”。高频触发词：并存、的、悬停、各、唯一。
- 实例：
  - 原文：44 生效于**导航项**与**悬停依赖的交互**，输入框/普通按钮不在其列
  - 改写：44 生效于**导航项**以及**依赖悬停状态的交互**，输入框和普通按钮不在其列
- 自查：句末是不是挂着孤零零的“的”？把“A 的 B”倒过来问：本意是 A 依赖 B，还是 B 依赖 A？

**数量词与领属定语后置**　✅ 双视角通过

- 病象：数量短语、指示代词放在描写性定语之前（一处可解的冲突）；领属、时间、处所定语可以在数量词之前（我的一本书、桌上的一本书）；“任何”放在领属定语之后（我的任何文件）。把数量词放到名词之后，或把领属定语挤到“任何”之后（任何我的文件），会割裂定中结构。
- 形式：把“数量词 + 描写性定语 + 名词”写成“描写性定语 + 数量词 + 名词”或“名词 + 数量词”，以及把“我的 + 任何 + N”写成“任何 + 我的 + N”，都是错位。高频触发词：一条、一处、一项、两笔、这个、任何。
- 实例：
  - 原文：冲突是可解的一处 rename/modify。先看准确文本。
  - 改写：这是一处可解的 rename/modify 冲突。先看准确文本。
  - 原文：（每文件恰好新测试一条变红）
  - 改写：（每个文件恰好有一条新测试变红）
  - 原文：工作树里现在只有本次改动，暂存区没有任何我的文件。
  - 改写：工作树里现在只有本次改动，暂存区里没有我的任何文件。
- 自查：数量词和“这个/那个”是不是站在描写性定语前面？“任何”是不是跟在“我的/他的”后面？

**虚词压缩与成分残缺**　✅ 双视角通过

- 病象：“的”“正在”等虚词和“是”“有”“约束”等动词不能省，也不能错序；省略后会使定语失去中心语、谓语缺失或动宾不完整（“队友的在改文件”应作“队友正在改的文件”；“不受这条要求”应作“不受这条要求约束”；“测试各页一份”应作“每页各有一份测试”）。残缺类的例子另见 5.3.3。
- 形式：“X 的 + 在 V”→“正在 V 的 X”；“测试各页一份”→“每页各有一份测试”；“不受这条要求”→“不受这条要求约束”。高频触发词：的、在、有、受、仅、已落。
- 实例：
  - 原文：服务账户以服务密钥登录，不受这条要求，只需显示名
  - 改写：服务账户以服务密钥登录，不受这条要求约束，只需填写显示名
  - 原文：取自平台名册读。测试各页一份（含 axe）。
  - 改写：取自平台名册。每页都有一份测试（含 axe）。
- 自查：每个分句都有明确的动词和宾语吗？“的”“正在”“是”“有”有没有被省掉或放错位置？

**把字句错配与动补割裂**　✅ 双视角通过

- 病象：“反射出”“受……限制”“改到”这类动补或介词结构是一个整体，中间不能插入宾语或插入语（“反射 DTO 出”应作“从 DTO 反射出”；“受 `-parallel`，默认 = `GOMAXPROCS` 限制”应作“受 `-parallel` 限制，其默认值为 `GOMAXPROCS`”）；宾语较长，或动词与“到”结合较紧时，用把字句更顺（“把三个包的测试迁到阶段模型”）。
- 形式：“V + 宾语 + 补语/介词”→“从/把 + 宾语 + V + 补语”；“V + 宾语 + 到 + 处所”→“把 + 宾语 + V 到 + 处所”；“把 A 改成 B 的错误实现”→“A 改成 B 这种错误实现”。高频触发词：出、到、受、把、改成。
- 实例：
  - 原文：补回两条依赖下限；改了三个包的测试到阶段模型
  - 改写：补回两条依赖下限；把三个包的测试迁移到了阶段模型
- 自查：动补结构中间是不是塞进了宾语或插入语？“把”字后面紧跟的是宾语吗？

**相邻成分假词**　✅ 双视角通过

- 病象：两个相邻成分各自无误，但字面连读会临时拼成一个假词或产生歧义（键模块、基本文件域、唯一使用），迫使读者回读；本质属歧义（花园路径），修法是挪开相邻成分、补“的”或加标点。
- 形式：把容易黏连的主语、序数词或范围副词挪开：“这个键 + 模块”→“模块……这个键”；“基本 + 文件域”→“文件域 + 基本”；“唯一 + 使用”→“只有 + 使用”；相邻几个字被重新切分：“上线路由”会被切成“上线／路由”，“称重生成”会被切成“称重／生成”，“表单独导出”会被切成“表单／独导出”，“读取代此”会被切成“读取／代此”。高频触发词：这个……+名词、基本+名词、唯一+动词；切分歧义的高发字：上、出、单、重、对、等、加、取。
- 实例：
  - 原文：DataTable 唯一使用 TableContainer，确认是否包 Paper
  - 改写：只有 DataTable 使用 TableContainer，确认是否用 Paper 包裹
  - 原文：宿主组装的是声明数组，各管理面的表单独导出
  - 改写：宿主组装的是声明数组，各管理面的表分别导出
- 自查：相邻两字会不会被读成一个假词？把主语、序数词或副词往前挪一格再读一遍。把这句话两个字一组念一遍，会不会念出别的词？
- 5.6.1 原“切分歧义”已并入本条。

#### 5.3.5 关联词/连词误用（语料 81 条）

**条件关联词错配**　✅ 双视角通过

- 病象：条件复句的配对关联词有定式：“只有…才…”“如果…就…”“一旦…就…”“若…则/就…”。前件误用“和/如果/若/一旦”而后件仍用“才”，或该用“只有”却写成“如果…才”，会造成条件与结果错配。“如果…才”口语中也有人说，正式文本改用“只有…才”。“只能…才…”是常见可接受说法，不在纠错范围；“只有”作限定副词（如“只有他知道”）时不要求后件带“才”，也不属本模式。
- 形式：把“只有 X 才 Y”写成“和 X 才 Y”“若 X 才 Y”“如果 X 才 Y”；把“一旦 X 就 Y”写成“一旦 X 才 Y”；“只有”作连词时后件缺“才”。高频触发：和…才、若…才、如果…才、一旦…才、只有（作连词时）…后件缺“才”。
- 实例：
  - 原文：如果你还想让 CI 在每次 `check` 通过后自动部署，才需要配这个仓库 secret
  - 改写：只有当你还想让 CI 在每次 `check` 通过后自动部署时，才需要配这个仓库 secret
- 自查：这句的条件词和结果词是原配吗？只有…才、如果…就、一旦…就，缺一个就补上或换掉。

**是否还是句式杂糅**　✅ 双视角通过

- 病象：“是否”“能否”“是不是”引出是非问，不能与“还是”引出的选择问叠用；应统一为“（确认/判断）是A还是B”。“是否A或B”中“或”处于“是否”的辖域内，属可接受说法，不属本模式。
- 形式：“确认/判断 X 是否 A，还是 B”“确认 X 能否 A，还是 B”；规范式为“X 是 A 还是 B”。高频触发：是否…还是、能否…还是、是不是…还是。
- 实例：
  - 原文：确认 settings 能否从配置文件取值，还是只能 seed 写入。
  - 改写：确认 settings 是可以从配置文件取值，还是只能由 seed 写入。
  - 原文：需要确认这是不是本次描述改动带的，还是并行改动
  - 改写：需要确认这是本次描述改动带来的，还是并行改动所致
- 自查：句子里同时出现“是否/能否/是不是”和“还是”了吗？二选一，只留“是…还是”。
- 5.6.1 原“句式杂糅”的一个实例已并入本条。

**顿号再叠以及**　✅ 双视角通过

- 病象：顿号已表示并列，其后不再接“以及”；应写作“A、B 以及 C”（以及前不加顿号），或直接“A、B、C”。并列项较长或为小句时，各项之间都改用逗号：“A，B，以及 C”。“且”“并”“或”“还”作连词时同理，前面不加顿号。
- 形式：“A、B、以及 C”→“A、B 以及 C”（“以及”前不加顿号），或直接“A、B、C”；“……？以及……”→“……？另外，……”。顿号后面除了“以及”，还常挂“且”“并”“或”“或是”“还”：词语并列就删去顿号，分句并列就把顿号改成逗号。高频触发：顿号+以及、顿号+与、顿号+且/并/或/或是/还、句首以及。
- 实例：
  - 原文：让我核对旁证：aliyun 是否同样把编号塞进错误、db logger 的先例、以及 poll 是否真可达。
  - 改写：让我核对旁证：aliyun 是否同样把编号塞进错误，db logger 有无先例，以及 poll 是否真可达。
  - 原文：现在补测试：搜索进行中的 a11y 扫描、以及翻页截断提示。
  - 改写：现在补测试：搜索进行中的 a11y 扫描以及翻页截断提示。
  - 原文：现在看本地化文件和现有的测试、以及 ui-b 的测试设置。
  - 改写：现在看本地化文件、现有的测试以及 ui-b 的测试设置。
  - 原文：提交与合并规矩、以及踩过的坑
  - 改写：提交与合并规矩以及踩过的坑
- 自查：顿号后面紧跟作连词用的“以及”“且”“并”“或”“还”吗？有就删掉顿号，或改用逗号。只看顿号后面是不是一个完整的连词，“并行”“还原”这类首字碰巧是连词的词不算。
- 5.1.2 原“顿号与连词叠用”已并入本条。

**“与”连接分句或动宾**

- 病象：“与”只连接名词性成分。拿它连接两个动宾短语，或者把名词和“是否”小句并列，两边结构不对称，读者容易把前后两部分误读成一个名词短语。改用逗号加“并”“再”“以及”，或者拆成两句。
- 形式：动宾短语＋与＋动宾短语；名词＋与＋是否小句。
- 实例：
  - 原文：现在取样例模块文档与全树搜索三个新模块的痕迹。
  - 改写：现在读取样例模块文档，并在全树搜索三个新模块的痕迹。
  - 原文：检查输出里的计数与是否真是同一条规则。
  - 改写：检查输出里的计数，并确认是否真是同一条规则。
  - 原文：现在并行：修设计文档里那几处错，与起 notification 实施轮。
  - 改写：现在并行做两件事：修设计文档里那几处错，同时启动 notification 实施轮。
- 自查：“与”两边都是名词吗？有一边带动词或“是否”，就用逗号断开。

#### 5.3.6 被动句滥用（语料 36 条）

**被字句塞双宾语**　✅ 双视角通过

- 病象：“被”字句的主语通常应是受事；若把处所、工具或事件当主语，动词后还带一个受事宾语/数量宾语，就会把两个论元挤在一起（仓库被推进了两个提交、请求被答 404、回调被递到事件 X）。注意：“他被授予一等奖”“他被选为班长”的主语是接受者，动词本身也允许带宾语，属规范句式；主语是领有者的（他被偷了钱包）同样规范。两类都不触发。
- 形式：“主语 + 被 + 动词 + 宾语/数量补语”；如被答 404、被推进两个提交、被递到事件 X。
- 实例：
  - 原文：仓库在本次运行期间被并行推进了两个提交
  - 改写：本次运行期间，仓库里并行新增了两个提交
  - 原文：违反时没有租户头的请求被 `tenant.resolve` 答 404
  - 改写：违反时，`tenant.resolve` 对没有租户头的请求返回 404
  - 原文：所以挂到受授权守卫的端上也不会被答 403。
  - 改写：所以挂到受授权守卫的端点上也不会得到 403。
- 自查：被字句的主语是处所、工具或事件，动词后又挂着受事或数量宾语吗？两条都成立才改；主语是接受者或领有者时不改。

**被字句接“变+形容词”**　✅ 双视角通过

- 病象：“变假”这类词表示状态变化，不能带受事，也就不能进“被”字句；“被 + 施事 + 变 + 状态词”是直接病句。只针对“变+形容词”结构，不要把本身可带宾语的“改变”“变成”算进来。“被驱动成错误”把出错说成被动的结果，同属本条，改成“……出错”或“……进入错误状态”。
- 形式：“主语 + 被 + …… + 变/成 + 状态词”；如被……变假、被……变大、被……变坏、被驱动成错误。
- 实例：
  - 原文：接下来按措辞扫一遍会被本次改动变假的句子。
  - 改写：接下来按措辞扫一遍会因本次改动而失实的句子。
- 自查：“被”后面跟的是能带受事的动作，还是一个状态？

**名词化套被字**　✅ 双视角通过

- 病象：把动作先名词化，再在外面套“被”，是英文名词化句式的残留，表现为两类：①生造的名词化动词套“被”（被文档化）；②“动作名词 + 被 + 完成/进行”（推送这一动作已被别的会话完成）。注意：被优化、被规范化、被数字化已是常规用法，不触发。
- 形式：“被 + X化”或“动作名词 + 被 + 完成”；如被文档化、推送这一动作被完成。
- 实例：
  - 原文：仓库里记录的是**另一种冷启动竞态**，且被反复、显式文档化
  - 改写：仓库里记录的是**另一种冷启动竞态**，文档里反复、明确地写到过它
  - 原文：推送这一动作已被别的会话完成，无需重推。
  - 改写：别的会话已经推送过了，无需重推。
- 自查：这个动作能直接用动词说吗？能就别先名词化再套“被”。

**英文被动谓语直译**

- 病象：把英文的被动谓语逐词搬成“被期待”“被告知”，汉语里不这么说。改成主动句，把施事提到主语位置，或者换成名词性说法。正常的被动句（被删除的文件、被拒绝的请求）不在此列，见第八节。
- 形式：被期待＋动词、被告知的＋名词、会被执行，对应英文的 be expected to、the N I was told about、will be enforced。
- 实例：
  - 原文：接缝被期待怎么用
  - 改写：扩展点的预期用法
  - 原文：这不属于我被告知的四份文档，但可能指向真正的缺口。
  - 改写：这不在交给我核对的四份文档之内，但可能指向真正的缺口。
  - 原文：依赖「这两个预算默认关闭」的装配现在会被执行
  - 改写：依赖“这两个预算默认关闭”的装配，现在会受到这两个预算的约束
- 自查：这个“被”字句能逐词还原成一句英文被动句吗？能，就改成主动句再读一遍。
- 说明：第一例原文后面跟着一个内部源码路径，已截去；改写里“接缝”按第六节换成“扩展点”。
- 5.2.1 原“英文句法照搬致成分残缺”的被动式实例已并入本条。

#### 5.3.7 人称与指代（语料 71 条）

**“它”接力漂移**　✅ 双视角通过

- 病象：“它”指代不明：同一句或相邻句中出现两个以上“它”而所指对象各不相同，读者无法判断每个“它”代的是谁；或“它”前面根本找不到唯一可回指的名词。两个以上“它”同指一个对象不属此列。
- 形式：同一句或相邻两句出现两个以上“它”，或“它”前找不到唯一先行词。高频触发：由它生成、等它落完、让它……、它要求、对着它。
- 实例：
  - 原文：我先 rebase 到它上面，把那五笔的冲突就地解掉，等它落完再 rebase 一次即可。
  - 改写：我先 rebase 到 `abc1234` 上，把那五笔的冲突就地解掉，等 `designer` 分支落完再 rebase 一次即可。
  - 原文：这就是 orval 用 mutator 而不是让它生成全部代码的用意
  - 改写：这就是让 orval 通过 mutator 调用手写请求层，而不让 orval 生成全部代码的用意
- 自查：落笔时每个“它”都能立刻换成具体名字吗？换不出就写名字。

**序数指代错位**　✅ 双视角通过

- 病象：用“前者／后者／后三者／其中”回指前面的并列项时数错了项，或把不在集合里的东西算了进去，结论直接指错对象。
- 形式：前文列 N 项，后文写“后者”实际想说第 M 项（M≠2）；或列了三项却用“后三者”指另外三项；或“其中”的范围与前句集合不符。高频触发：前者、后者、后三者、其中。
- 实例：
  - 原文：涉及的包有五个：`ui-a`、`lib-a`（仅注释）、`lib-b`（仅错误前缀）、`ui-b`、`ui-c`（仅测试引用）。后三者都不是真正的类型依赖。
  - 改写：涉及的包有五个：`ui-a`、`lib-a`（仅注释）、`lib-b`（仅错误前缀）、`ui-b`、`ui-c`（仅测试引用）。其中带括注的三个包都不是真正的类型依赖。
  - 说明：原摘录从半句截起，这里按原文语境压缩成一句，包名已替换；原文的“后三者”实指三个带括注的包，并不是最后三项。
- 自查：上一句真的一一列出了这些项吗？先数一遍再用序数词。

**当面称“用户”**　✅ 双视角通过

- 病象：明明在跟用户本人说话，却把对方写成第三方“用户”，同一段又用“你”，人称在句与句之间来回跳。
- 形式：给用户的汇报里出现“用户要求／用户问的是／给用户的总结”，同段又用“你”；或“用户你”并置。高频触发：用户要求、用户问的是、给用户的、用户你、用户描述。
- 实例：
  - 原文：**前端已经是用户描述的那种形态**：`web/` 是个 pnpm workspace
  - 改写：**前端已经是你描述的那种形态**：`web/` 是个 pnpm workspace
  - 原文：我会记录并在给用户的总结里如实列出，而不是无限追下去
  - 改写：我会记录下来，并在给你的总结里如实列出，而不是无限追下去
  - 原文：仓库当前没有测试在跑。用户问的是估时，我直接实测最可靠
  - 改写：仓库当前没有测试在跑。你问的是估时，最可靠的办法是直接实测
- 自查：我这句话是写给谁看的？对方就是“你”，不是“用户”。

**非人主体人称混乱**　✅ 双视角通过

- 病象：指代非人对象（会话、agent、工作树、界面元素等）时，人称或单复数前后不一致：对无生命物用“他”，用“他们／它们”指代单一对象，或同一段内“它”“他”“他们”交替使用，使读者误以为是不同对象。对 AI agent 选“它”还是“他”属风格问题，不算错；错在不一致，以及对无生命物用“他”。
- 形式：前文只有一个 engineer 或会话，后文写“他们……”；或同一段“它做了……”与“他的……”“它们……”混用。高频触发：他们提到、他们指出、他们自己、他的 fill、它们问我。
- 实例：
  - 原文：他的 `fill` 是字面量，明暗共用；玻璃的浅色半透明白到深色模式仍然是白。
  - 改写：它的 `fill` 是字面量，明暗共用；玻璃的浅色半透明白在深色模式下仍然是白。
- 自查：这个对象是人是物、是单是复？整段只留一个代词。

**“该”字粘连**　✅ 双视角通过

- 病象：单用“该”指代时，与相邻字连读成另一个常用词，如“删除该死代码”会被读成“该死”＋“代码”，“触发该死锁”会被读成“该死”＋“锁”。（“该节”“该笔款项”等是正式书面语的规范用法，不属此列。）
- 形式：“该”与后面的字连读成另一个词：该／死代码、该／死锁。高频触发：该死代码、该死锁、该死循环。
- 实例：
  - 原文：`FooIdentity` 已无消费方，删除该死代码及其导入。
  - 改写：`FooIdentity` 已无消费方，删除这段死代码及其导入。
  - 原文：复现脚本已经能稳定触发该死锁，下一步加超时日志。
  - 改写：复现脚本已经能稳定触发这个死锁，下一步加超时日志。
  - 说明：本例为自拟。
- 自查：“该”和后面那个词连起来读，会不会变成另一个词？

**指示词悬空**

- 病象：“这”“该问题”“这两行”“二者”这类指示词在前文找不到唯一可指的对象，读者只能靠猜。前文没提过这样东西，或者可能的对象不止一个，都算。“该”字和后一个字连读成词的问题见“‘该’字粘连”。
- 形式：该＋名词、这＋数量＋名词、二者，前文没有先行词，或先行词不止一个。
- 实例：
  - 原文：我补一个跨构建标签的编译检查（拆分重构最易出现该问题）
  - 改写：我补一个跨构建标签的编译检查（拆分重构最容易在这方面出问题）
  - 原文：按通则回写设计文档末尾的「实现状态」表（只改这两行）
  - 改写：按通则回写设计文档末尾的“实现状态”表（只改采集层相关的两行）
  - 原文：ADR 的「背景」与「考虑过的选项」两节内容关系紧密；为准确判断该节的归属
  - 改写：ADR 的“背景”与“考虑过的选项”两节内容关系紧密；为准确判断这部分内容的归属
- 自查：每个“这”“该”“二者”往前找，能找到唯一的那个对象吗？

**主语错位暗换**

- 病象：句首放的是受事、处所或工具，后面却接一个只有施事才能做的动作，读者会把动作安到句首成分上。
- 形式：受事或处所＋施事才能做的动词：对象调用、工作树跑完检查、这句话回来删掉。
- 实例：
  - 原文：同一个对象调用两次 `Supply`，分别给两个不同模块（比如一次按类型认领、一次指名）
  - 改写：对同一个对象调用两次 `Supply`，分别预置给两个不同模块（比如一次按类型认领、一次指名）
  - 原文：工作树跑完检查不变。
  - 改写：跑完检查后工作树没有变化。
  - 原文：功能一旦开发，这句话必须回来手工删掉，且它不可验收、没有 id、扫不出影响面。
  - 改写：功能一旦开发完成，就得回头手工删掉这句话；而且它不可验收、没有 id、扫不出影响面。
- 自查：句首这个名词真能做后面这个动作吗？不能，就把真正的施事补出来，或者用“对”“把”引出它。

#### 5.3.8 时体标记误用（语料 11 条）

**未然事态带了**

- 病象：还没做或只是要求做的事，用完成体“了”来说，读起来像已经做完，又像英文 had to 的直译。只管“必须／需要＋动词＋了＋宾语”这一种。句末表示变化的“了”（必须走了、需要休息了）和表示条件完成的“了”（必须签了字才能进）都正确。
- 形式：必须／需要／还得＋动词＋了＋宾语。
- 实例：
  - 原文：另外必须新增了一个 `.github/actionlint.yaml` 登记自定义标签
  - 改写：另外还不得不新增一个 `.github/actionlint.yaml` 来登记自定义标签
- 自查：这件事做完了吗？做完了就去掉“必须”，换成“不得不”或直接陈述；没做完就去掉“了”。

#### 5.3.9 冗余成分（语料 103 条）

**同义叠床架屋**　✅ 双视角通过

- 病象：在同一分句之内叠用两个词义相同或相近的词，两个词不必紧挨，删去其中一个后语义不变，句子更顺；分处不同分句、各自承担新信息的近义词不算。同一句用“以下”“下列”两个指示词指同一组对象，也属此类。“继续保持”中的“继续”是体貌修饰，不是“保持”的同义重复，不算叠用。
- 形式：“近义词 A ＋ 近义词 B”并置，或隔几个字出现在同一分句里，删掉一个句子仍成立；同一句用“以下”“下列”指同一组对象时删掉一个。高频组合：默认/缺省、已有/现存、已有……既有、遗留/legacy、最早/初始、唯一/只有、属于/归、核实……确认、以下/下列、约……几、大约……左右、首先……第一、免费赠送。
- 实例：
  - 原文：默认 `ErrorResponder` 缺省时渲染 `application/problem+json`
  - 改写：未配置 `ErrorResponder` 时默认渲染 `application/problem+json`
  - 原文：**前端已有一个现存的「功能开关」面，它指向一个后端并不存在的 legacy 端点。**
  - 改写：**前端已有一个“功能开关”界面，它指向一个后端并不存在的 legacy 端点。**
  - 原文：**结论**：该次轻量 race 运行完全全绿。
  - 改写：**结论**：该次轻量 race 运行全绿。
  - 原文：以下依据均来自下列四个页面：`https://mui.com/material-ui/react-card.md`
  - 改写：以下依据均来自四个页面：`https://mui.com/material-ui/react-card.md`
  - 原文：（有约几秒的「无当前组织」过渡直到名册读回）
  - 改写：（有几秒的“无当前组织”过渡直到名册读回）
  - 原文：仓库里已有对连接错误分类的既有做法，我先看 `pkg/db` 和 `pkg/kv` 的分类逻辑
  - 改写：仓库里已有对连接错误分类的做法，我先看 `pkg/db` 和 `pkg/kv` 的分类逻辑
- 自查：这句话删掉其中一个近义词还成立吗？成立就删。
- 5.2.6 原“同义成分叠用”已并入本条，5.1.3“同一名称写法不一”原有的“以下”“下列”重复的内容也并入了本条。

**同词紧邻复现**　✅ 双视角通过

- 病象：非修辞需要，同一个词在短距离内重复出现，删去其一或换个说法后不损义，读起来像口误、拗口或造成歧义。两个词交界处同一个字紧挨着出现（并＋并行、如需要＋要、错的＋的），语法上未必错，读起来却打结，也属本条。改法是加逗号，或换掉其中一个字。同一个字隔开几个字偶然共现不算，合法的重叠式（看看、人人、渐渐、仅仅、好好地）也不在此列。
- 形式：“X……X”短距离复现，如“每一行断言行”；词与词交界处同字相连：并并行、如需要要、错的的、已经经。高频触发字：也、再、带、读、开、行、项、说明、处置、层。
- 实例：
  - 原文：现在直接用 `gin.HandlerFunc` 与 `*gin.Context`，也就是也 import gin
  - 改写：现在直接用 `gin.HandlerFunc` 与 `*gin.Context`，也就是说同样导入了 gin
  - 原文：我先看表头调整后的实际效果，再整体再审一遍配色。
  - 改写：我先看表头调整后的实际效果，再整体审一遍配色。
  - 原文：需要核对线上配置。先看运行配置的文件位置，只读读取配置文件。
  - 改写：需要核对线上配置。先看运行配置的文件位置，以只读方式读取配置文件。
  - 原文：接下来跑仓库的 web 门禁，并并行做一轮独立审查。
  - 改写：接下来跑仓库的 web 门禁，同时做一轮独立审查。
  - 原文：### 4.1 会变成**错的**的现行断言（必须改，不是润色）
  - 改写：### 4.1 会变成错误的现行断言（必须改，不是润色）
- 自查：同一个词在几个字之内出现两次了吗？删掉或换掉一个，意思不丢吗？有没有两个字挨在一起重复了？念一遍就知道。
- 5.6.1 原“同字连用”已并入本条。

**赘余虚词**　✅ 双视角通过

- 病象：句中多出一个虚词、连词或数量词，删掉后句意和句法都不变，读起来还更顺，如“已被……后”里与“已”重复的“后”，“一个整份文件”里与“整份”重复的“一个”。只是可省的不算错，删掉后明显更顺才改。
- 形式：已被……后／一个整份文件／主谓短语后多“的”／动词后多“来”。
- 实例：
  - 原文：报错的定位到 `location.Path` 无扩展名，说明 `DefaultLocator` 被 env 覆盖了
  - 改写：报错定位到 `location.Path`，该路径没有扩展名，说明 `DefaultLocator` 被 env 覆盖了
- 自查：删掉这个虚词或连词，意思不变，而且读起来更顺吗？两条都满足才删。

**生造压缩词**：见 5.2.2“生造缩略词（截字造词）”。

### 5.4 数量

#### 5.4.1 量词/数字/单位用法（语料 166 条）

**数字悬空**　✅ 双视角通过

- 病象：数词后省略量词、单位、中心语或谓语，数字就悬空。典型是数词直接修饰双音节实体名词（“80 文件”“两语言”“六目标”），或数量短语直接作谓语而缺“有”“共”，或缺“的”及中心语。单音节名词（人、天、年、页、行）可直接受数词修饰，不属此列。表格单元格、表头和统计行（如“0 错误 / 3 警告”）可以省量词；正文句子和句中括号注不省。
- 形式：“数词 + 名词”直接连写：80 文件、两语言、六目标；数量短语直接作谓语，缺“有”“共”：同一处事实六个载体；缺“的”或中心语：两语言键集合、Registry 七方法。
- 实例：
  - 原文：W1 完成（提交 `abc1234`，80 文件，全门禁绿）
  - 改写：W1 完成（提交 `abc1234`，80 个文件，全部门禁通过）
  - 原文：同一处事实六个载体，本轮只改了一半
  - 改写：同一条事实有六个载体，本轮只改了一半
  - 原文：改动只有这四个文件，两语言键集合完全一致。
  - 改写：改动只有这四个文件，两种语言的键集合完全一致。
- 自查：每个数字后面，量词、单位、谓语都齐了吗？

**数目与列举不符**　✅ 双视角通过

- 病象：先报总数再列举，总数必须等于列举项数；对不上时读者不知道该信数字还是信清单，整段的可信度就没了。
- 形式：“N 条／类／项／列……”后面跟冒号或括号列举，但 N 与实际项数不等；也见于“四列表”实际只有三列这类数目与内容不符的情况。
- 实例：
  - 原文：用户列的四类通用件（ops、API 错误体/绑定、worker、标识键工具、宿主六件套）
  - 改写：用户列的五类通用件（ops、API 错误体/绑定、worker、标识键工具、宿主六件套）
  - 原文：**模块文档用四列表**（能力 / 状态 / 代码）
  - 改写：**模块文档用三列的表**（能力 / 状态 / 代码）
- 自查：写完“N 条”“N 项”后，回头数一遍括号里的条目。

**数量短语错位**　✅ 双视角通过

- 病象：数量短语要紧贴它真正修饰的中心语；放在“别的 X 的 Y”或引用词前面，读者会先把它算到 X 上。
- 形式：“N 个 + 别的／其他 + 名词₁ + 的 + 名词₂”应改为“别的名词₁ 的 N 个名词₂”；“30 行‘产物’”这类数量直接压在引用词前，应改为“含‘产物’的 30 行”。
- 实例：
  - 原文：主检出仍有 19 个别的会话的在途文件，暂不能合。
  - 改写：主工作树上仍有别的会话的 19 个在途文件，暂不能合。
  - 原文：而不变量 9 已改为"实例"。把 30 行"产物"全部列出逐条判断。
  - 改写：而不变量 9 已改为“实例”。把含“产物”的 30 行全部列出逐条判断。
- 自查：数字紧挨着的名词，是不是它真正要数的那个？
- 与 5.3.4“数量词与领属定语后置”同机制。

**数量体例前后不一**　✅ 双视角通过

- 病象：同一段或同一份清单里，汉字数字与阿拉伯数字、全角与半角符号、同类对象的量词或计数口径随意换用，体例像拼贴，还容易被误读成不同对象。
- 形式：同句出现“五处……4 处”；同一清单混用“3 个 / 43 / 114”“四项 / 四处”；全角 `＋` 与半角 `+` 并存；同一对象前后换量词。
- 实例：
  - 原文：**为什么不用共享助手。** 这五处只有 4 处要改、每处一行
  - 改写：**为什么不用共享辅助函数。** 这五处只有四处要改，每处一行
  - 原文：删除 3 个(容器竞态与桩用例)、新增 43(标记文件＋compose＋ADR＋定时工作流)、改动 114
  - 改写：删除 3 个（容器竞态与桩用例）、新增 43 个（标记文件＋compose＋ADR＋定时工作流）、改动 114 个
- 自查：同一段或同一张清单里，同类对象用的是同一个量词和写法吗？

**量词张冠李戴**

- 病象：量词和名词的语义类别对不上，母语读者一读就觉得别扭。“处”管位置，不配文件、文档；“位”是对人的敬称，不配会话、进程。“一台引擎”“一棵树”这类常规搭配不在此列。
- 形式：数词＋错类量词＋名词：三处文件、四处文档、另一位会话。
- 实例：
  - 原文：现在改 audit ADR 里引用「模式」的三处文件
  - 改写：现在改引用了“模式”的三份 audit ADR
  - 原文：另一位会话已写过完整的端到端规矩
  - 改写：另一个会话已写过完整的端到端规矩
  - 原文：对四处编辑文档的**每一个** mermaid 图跑 `mmdc`
  - 改写：对编辑过的四份文档中的**每一个** mermaid 图跑 `mmdc`
- 自查：这个量词平时配哪一类事物？跟眼前的名词是同一类吗？

**二与两误用**

- 病象：在量词前计数时用了“二”。普通量词前计数用“两”，如两个分支、两行；“二”用于读数、序数和多位数，如第二、十二、二十。把“二”换成“两”时，漏掉的量词也要补上。
- 形式：二＋量词或名词表示数量：二分支、二行。
- 实例：
  - 原文：`message()` 从三分支降到二分支
  - 改写：`message()` 从三个分支减为两个分支
- 自查：这个“二”是在计数吗？是就换成“两”，再看量词齐不齐。

**英文术语硬译**：见 5.2.1“工程行话字面直译”。

### 5.5 语体

#### 5.5.1 口语与书面语混用（语料 19 条）

**网络热词直入文档**　✅ 双视角通过

- 病象：用网络流行语替代可定义的中性说法（翻车→出错、手搓→手写、唯二→仅有的两处、人话→通俗说法），语体失配，表述也不够精确，不便检索。适用于文档、报告和给别人看的回复；博客和随笔按 checklist.md 3.5 的口径。
- 形式：用网络流行语替代中性说法：翻车、翻车点、唯二、人话、手搓。触发条件是句子在描述失败、缺陷或进度时，选了一个带情绪的流行语，而不是可定义的词。
- 实例：
  - 原文：并把这次翻车的经过与两条实测事实
  - 改写：并把这次出错的经过与两条实测事实
  - 原文：唯二仍 `range stacks` 的 `wiring_test.go:187,221` 是**静态 roster 校验**
  - 改写：仅有的两处仍用 `range stacks` 的 `wiring_test.go:187,221` 是**静态 roster 校验**
- 自查：这句里的“翻车”“手搓”“唯二”换成中性说法还成立吗？不成立，说明它在靠梗表意。

**单字口语动词代书面词**　✅ 双视角通过

- 病象：在正式技术文本中，用俚语化或生造的单音节动词替代规范书面动词（吃→访问、答→返回、打→标记、开做→开始实施、拉→引入），造成搭配生硬、语体随意或语义含混。判断依据是动词是否俚语化、生造以及它与宾语的搭配是否成立，而不是音节数；读、写、调、跑、起等常规单音节动词不属本模式。
- 形式：把“标记／访问／接受／返回／引入／新增／纠正”压成一个字：打→标记、吃→访问或接受、答→返回、开做→开始实施、拉→引入、长→新增、纠→纠正。触发条件是技术动作前只有一个单字动词，后面直接跟宾语、状态码或“起来”。
- 实例：
  - 原文：只调 `markFoo`（**打本租户的 contact**），**完全不碰平台表**
  - 改写：只调 `markFoo`（**只标记本租户的 contact**），**完全不碰平台表**
  - 原文：同样走守卫、同样吃数据库，语义就名实相符
  - 改写：同样走守卫、同样访问数据库，语义就名实相符
  - 原文：网关先对不在允许集合的路由答 401。
  - 改写：网关先对不在允许集合内的路由返回 401。
- 自查：这个单字动词在书面语里有这个义项吗？“吃数据库”“答 401”“打 contact”只在口头行话里成立，换成访问、返回、标记；读、写、调、跑、起不用换。

**CI 黑话替代结论**　✅ 双视角通过

- 病象：把测试与命令的口头黑话（红、绿、挂、退 0、计时跑、守门）原样写进书面结论或报告，以屏幕颜色、口头计数或动词缩略代替“通过／失败／退出码／运行”等规范表述，造成语体失配，并降低结果的可核验性。适用于一切报告结果的句子，包括会话里的进度汇报。先给出定义的术语，如 10.3 的“假绿”，不在此列；工程语境里说 CI“全绿”“报红”可以，但正式报告里要写明检查项和结果。
- 形式：“会红”“全部绿”“照绿”“9 过 2 挂”“退 0”“计时跑”“守门”。触发条件是描述测试或命令结果时，用的是屏幕颜色、口头计数或动词缩略，而不是“通过／失败／退出码／运行”。
- 实例：
  - 原文：结构检查退 0。现在渲染五份文档里的每一个 mermaid 图块。
  - 改写：结构检查退出码为 0。现在渲染五份文档里的每一个 mermaid 图块。
  - 原文：`auth.foo`）——这是会红、需要跟着改的既有测试之一
  - 改写：`auth.foo`），这是会失败、需要跟着改的既有测试之一
  - 原文：全量 `make check` **退 0**。看它跑了什么，然后落 main。
  - 改写：全量 `make check` 退出码为 0。看它跑了什么，然后合入 main。
- 自查：没看过那块终端的人，能从我这句话知道哪几项通过、哪几项失败吗？

**口语判断句下结论**

- 病象：用“是真的”“是假话”“很硬”这类口头判断下结论，只给态度，不给可核验的依据。正式文本应换成属实、与事实不符、论证充分、已失效这类事实性说法。适用于文档、报告和给别人看的回复；博客和随笔按 checklist.md 3.5 的口径。
- 形式：结论位置上的口头判断：是真的、是假话、很硬、已死。
- 实例：
  - 原文：直接冲突。引文所附带「漏掉短信首登开户」也是真的。
  - 改写：直接冲突。引文附带的“漏掉短信首登开户”也属实。
  - 原文：AWS 按国家注册状态无法表达，`Approval` 恒 Approved 是假话
  - 改写：AWS 按国家注册状态无法表达，`Approval` 恒为 Approved 与事实不符
  - 原文：但它推翻的 ADR 很硬
  - 改写：但它推翻的 ADR 论证充分
- 自查：这个结论词能让读者拿去核对吗？把“很硬”“是假话”换成“论证充分”“与事实不符”，再看依据写出来没有。

**小节标题口语化**　✅ 双视角通过

- 病象：正式文档的小节标题里出现口语成分，如“东西”这类空泛名词、“点到底”“怎么落的”这类口头说法，读者无法从目录一眼判断本节内容。问句标题本身可以用，要改的只是其中的口语成分。适用于设计、审查等正式文档，内部便签可放宽。
- 形式：“## 现在在跑的东西”“## 四条需求怎么落的”“## 验收怎么点到底”。触发条件是标题里出现“东西”“怎么落的”“点到底”这类口语成分。
- 实例：
  - 原文：## 现在在跑的东西
  - 改写：## 当前运行的服务
  - 原文：## 验收怎么点到底，不需要后端改动
  - 改写：## 逐项点击验收（无需改动后端）
- 自查：标题里有“东西”“点到底”这类口头说法吗？把标题缩成目录里的一行，别人能凭它知道这节的内容吗？

**口语省略致成分残缺**：见 5.3.3“及物动词缺宾语”“谓语残缺”和“中心语残缺”。

### 5.6 逻辑与事实

#### 5.6.1 其他（语料 96 条）

**前后自相矛盾**　✅ 双视角通过

- 病象：同一段或紧邻的前后文中两个判断互相否定：漏掉或误加否定词，把关系或范围说反，读者无法同时接受两句话。总数与列举项数不符见 5.4.1“数目与列举不符”；术语前后不一致属于术语统一问题，不并入本条。
- 形式：“值得／不值得”“会／取决于”“一对多／多对一”“全部落在 X／其中一条在 Y”“抽查／全部”“对称／不对称”；定稿前回头核一遍正反。
- 实例：

  - 改写：因为这个场景很少见，不值得为它换掉约定
  - 原文：抽查全部 IconButton 是否带可及名。
  - 改写：逐一检查全部 IconButton 是否带可访问名称。
  - 原文：与 architecture 禁止子模块行的对称校验（`829-834`）不对称
  - 改写：与 architecture 禁止子模块行的校验（`829-834`）不对称
- 自查：这句话里的正反能对上吗？说“会”就别接“取决于”，说“全部”就别接“抽查”或“其中一条”。

## 八、不算错误，不要矫枉过正

- 技术术语保留英文并加代码标记：`commit`、`rebase`、`token`、`API`、`hook`、`harness`。
- 已被汉语吸收的行业词：落地、收敛、闭环、对齐、兜底、颗粒度、降维。用准了就不改；用错义项才改，例如“收敛”指范围逐步缩小，写成“把大家的意见收敛上来”，意思是收集，就错了，应写“汇总”。
- 口语化但不别扭的说法：跑一遍测试、看一眼、拿掉。“让我看看”“让我来”是正常的汉语自述。
- 中英之间加不加空格属于排版习惯，不按错误处理；但同一处两侧要对称，同一份文档要统一。
- “形状”指物理外形时正确；只有用来指数据结构或接口形态时才是 shape 的硬译。
- 字面义或行业义正确的词：回落（数值下降）、镜头（摄影）、入口（程序入口、入口函数）、墙钟时间、代码路径、执行路径、基于性质的测试，以及工作树和管理面、控制面、数据面这类领域专名。与上一条“形状”同理。
- 正常的被动句：被删除的文件、被拒绝的请求、未被触及、问题被解决。“少用被”管的是英文被动的直译（被期待、被告知的文档），不是一切“被”字。
- 形式动词搭配：做检查、做一次验证、进行改革。“进行”“作出”只在删掉后仍通顺时才删。
- 体标记与关联词：“没去过”“必须走了”“虽然 A，B 却……”“讨论并通过”“确认是否 X，否则 Y”。
- 数字写法：千分撇（1,536）、技术文本里的 13k、表格和统计行里的“0 错误”。表格单元格、表头和统计行可以省量词，正文句子和句中括号注不省，见 5.4.1“数字悬空”。
- “今天”可以指现今、目前，“今天的行为”不算错，最多是风格建议。“多因素认证”“第二因素”是正确说法。
- 问句可以作小节标题；要改的只是标题里的口语成分，见 5.5.1“小节标题口语化”。
- 术语第一次出现时的“中文（English）”括注，不算中英同义并用。
- 工程语境里的“全绿”“报红”“变红”指 CI 和测试状态，可以用；给圈外人看的文章要先定义。
- 项目术语表和代码标识符的既定译名（如 `Carrier` 译“载体”）优先于本库的硬译表，见 10.7。领域惯例同理：读屏语境的“播报”，消息、事件、RPC 语境的“消费者”“消费方”，限流、哈希、存储语境的“桶”，git 和区块链语境的“分叉”，git 语境的“回退这个提交”，以及“暴露端口”“暴露服务”“暴露问题”这类带宾语的说法。地址族、协议族、字体族是术语。

## 九、方法与局限

1. 语料是这台机器上 Claude Code 保留下来的转录，时间跨度约 17 天，其中 99% 以上来自同一个内部项目。
2. 审查对象是助手的输出，不是用户的原话；用户的引述、文件原文、代码块不计入。
3. 第一轮共报出 17,347 条疑似问题，复核保留 7,305 条，逐字回查原文命中 7,051 条（96.5%），去重后 7,047 条进入统计。未命中的 5 条与 80 个来源文件在审查期间已被清理的条目，未进入样例库。
4. 分类由模型判断，个别条目的类别可能偏一格，但摘录与问题是逐字核对过的。
5. 每条模式又经过两名独立审校者交叉核实，双方都通过的标“✅ 双视角通过”。第五节里不带这个标记的条目是后来复核收入的，有的从附录一收回，有的由原条目拆出；第十节的条目经用户确认后追加，不走这道核实。个别条目标“存疑（未双视角核实）”，是复核时拆出或补了实例、还没有过双视角核实的。
6. 122 个审查分块中有 4 个（均为工作流子代理的内部文本）核实环节未能完成，其条目不计入统计。
7. 2026-11-11 起本机引号体例改为只用“”（内层‘’）。本库的说明文字和“改写”行已随之统一；“原文”行和附录一的否决理由保留审查当时的写法，其中的 `「」` 是语料原貌，不是推荐写法。

## 十、后续增补

> 建库之后在使用中新发现、经用户确认的模式，按日期追加。每条按第五节体例写病象、形式、实例、自查，标题后注明日期；来源和合并日期记在 additions.md。

### 10.1 比喻直译（2026-11-12）

- 病象：把英文里的常规比喻照搬进中文，把抽象关系说成实物。gap 译“缝隙”、fossil 译“化石”属此类。entry point 只在指“问题从哪里进来”时才算，程序入口、入口函数是正常术语。中文有现成说法（落差、鸿沟、断层、证据、痕迹、途径）就用现成的，没有就说白话。同类见 5.2.1“工程行话字面直译”。
- 形式：抽象关系配上实物名词：A 和 B 之间隔着一道缝隙、X 是旧设计的化石、Y 是问题的入口。
- 实例：
  - 原文：绿色徽章和需求已满足之间，隔着一道结构性的缝隙。
  - 改写：绿色徽章和需求已满足之间，有一段结构性的落差。
  - 原文：契约被悄悄偷换的最常见入口
  - 改写：契约最常被悄悄偷换的地方
- 自查：这个名词指的东西摸得着吗？摸不着却配上了“隔着一道”“从这里进来”这类实物说法，就换成中文现成的说法。

### 10.2 自造术语不能逐字直译（2026-11-12）

- 病象：把英文自造的术语逐字译成中文短语，读起来始终是译文。先找中文里同构的现成说法，再考虑成熟的构词格式，并按 10.3 在第一次出现前定义。
- 形式：英文的“形容词 + but + 形容词”或“名词 + 名词”自造术语，逐字换成对应的中文词再拼起来。
- 实例：
  - 原文：“绿色但错”（green but wrong）
  - 改写：“假绿”，第一次出现前先给定义
- 自查：去掉英文括注，中文读者还看得懂这个术语吗？念出来像不像译文？

### 10.3 自造术语要在开头定义，字义要明说（2026-11-12）

- 病象：术语里的字在中文里没有作者要的那层意思，而且定义放在文章后半。“绿”在一般中文里没有“测试通过”的义项，读者看不出“绿而不实”指什么。自造术语第一次出现前就定义，括注英文原词；只在行话里有特定含义的字要明说。
- 形式：用行话义项造词却不交代；定义出现在术语用过几次之后。
- 实例：
  - 原文：“绿而不实”
  - 改写：改用“假绿”，并在第一次出现前加一句定义：“绿”取程序员口头上的意思，指 CI 全部通过；“假”指这个绿没有兑现它暗示的东西。
- 自查：术语第一次出现之前有定义吗？里面的字在一般中文里有这个意思吗？放进评审口语里念一遍，同事听得懂吗？

### 10.4 拟人化动词直译（2026-11-12）

- 病象：无生命主语配上只有人才会做的动词（承诺、声称、相信、希望），是英文拟人写法的直译。主语是文件名、测试、配置这类对象时，动词换成“写的是”“说的是”“标的是”。“日志告诉我们”“数据显示”这类已被接受的说法不算。
- 形式：文件名、测试、配置、徽章＋承诺／声称／相信／希望。
- 实例：
  - 原文：名字承诺了一段用户旅程，内容只验证了路由没拼错。
  - 改写：名字里写的是一段用户旅程，内容只验证了路由没拼错。
- 自查：主语是人吗？不是人，动词却是承诺、声称、相信、希望，就换成“写的是”“说的是”。

### 10.5 硬译补四条：happy path、impulse、property、forbidden（2026-11-12）

- 病象：常见英文词按字面译成中文。happy path 译正常流程、主流程，代码路径、执行路径是术语，不改；impulse 译直觉、第一反应；property 在“具备……”里译特性，数学和测试语境（如基于性质的测试）用“性质”正确；forbidden 直接说禁止，不造“禁用语法”这类名词。第六节词表有对应的四行。
- 形式：happy path→正常路径，impulse→冲动，property→性质，forbidden→禁用语法。
- 实例：
  - 原文：拖慢了正常路径
  - 改写：拖慢了正常流程
  - 原文：最初的设计冲动
  - 改写：最初的直觉
  - 原文：具备我们要的几乎所有性质
  - 改写：具备我们要的几乎所有特性
  - 原文：软通过是禁用语法
  - 改写：软通过直接禁止
- 自查：不回译英文，中文读者能懂这个词吗？它在这个领域里是不是通行术语？

### 10.6 破折号、逻辑符号与括号注解（2026-11-12）

- 病象：正文里用 `——` 做补充、转折或制造停顿，用 `∧`、`∨`、`¬`、`⇒` 代替中文连词，用括号堆补充说明。用户在两个项目里多次反对，列为不用。引文里的破折号照原样保留。
- 形式：`A——B——C`；`(a1 ∧ a2) ∨ b`；一句话里塞一两个括号补充。
- 实例（自拟）：
  - 原文：这套设计最不一样的地方——主动缩小承诺范围——在 AI 工具领域讨论得还不多

  - 改写：满足下面任一条件即可合入：CI 和评审都已通过，或者属于紧急修复

  - 改写：这一步要先在本地跑迁移脚本，大约两分钟，CI 里不跑
- 自查：正文里有 `——`、`∧`、`∨`、`⇒` 吗？括号里的话能不能拆成一句？

### 10.7 既定译名优先于硬译表（2026-11-12）

- 病象：按硬译表机械替换，把项目术语表和代码标识符的既定译名（载体对应 `Carrier`、读屏语境的播报）也改掉，复核时全部回退。替换前先查项目术语表和代码标识符，再看这个词在它所在的领域里是不是通行说法。领域惯例见第八节。反过来，同一个词出了它的领域仍按硬译处理，例如用“播报”说请求头携带租户标识。
- 形式：载体→服务商；播报→发送；消费者→使用方（消息语境）；桶→分类（限流语境）。
- 实例：
  - 原文：我建议**把发件人放成载体配置项 `from`，`Message` 不含该字段**
  - 改写：（“载体”保留不改，它是 `Carrier` 的既定译名）
  - 原文：auth-ui 播报区可聚焦
  - 改写：（“播报区”保留不改，读屏语境的通行说法）
- 自查：替换前查过项目术语表和代码标识符了吗？这个词在它所在的领域里是不是通行说法？

### 10.8 表格里的空值占位不是破折号（2026-11-12）

- 病象：机械检查把表格单元格里单独一个 `—` 或 `——` 报成破折号。这类符号表示“无”或“不适用”，是表格占位符，中文表格的通行写法，不是正文里的破折号。单元格里成句的文字仍按 2.1 处理。
- 形式：`| 版本 | — |`、`| 备注 | —— |`。
- 实例（自拟）：
  - 原文：`| 依赖 | — |`
  - 改写：（保留，占位符不是破折号）
  - 原文：`| 说明 | 这条路径——见下文——不再使用 |`
  - 改写：`| 说明 | 这条路径见下文，不再使用 |`
- 自查：占位符是不是整个单元格只有 `—` 或 `——`？单元格里还有别的字时，按正文的破折号规则处理。
